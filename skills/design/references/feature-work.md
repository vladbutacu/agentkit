# Feature work

Keep one local record for a feature from intake through verification. The lead agent owns the record and hands off each step to the referenced skill in order. At every handoff or pause update `status.md` with the current step, artifact links and next action.

1. **Open or resume.** Use `.scratch/<feature-slug>/` in the repository. Check that Git ignores `.scratch/`. If needed, add `/.scratch/` to the local Git exclude file. If Git metadata is protected, add the rule to `.gitignore` for an implementation request. For design-only work in that case, use a writable scratch directory outside the checkout. Create `status.md` with the request and next action before the first design discussion, and link its absolute path in that discussion. On resume, reopen the existing record and read it, the linked artifacts and Git history. If execution moves to another worktree, carry the record there before dispatching work and report its new path.
2. **Design.** Inspect the code and use [brainstorming](brainstorming.md) for unresolved design decisions. Save the proposed design in `design.md` before presenting it for approval. If the user supplied an approved design, save or link that design. Record what was approved in `status.md` before production edits. For a design others will implement, use the independent design review in brainstorming.
3. **Plan.** Use [writing plans](writing-plans.md) and save `plan.md`. Design approval and authorization to implement cover a plan within that design. Bring any material scope or design changes back to the user. For ticket mode, use [to-tickets](to-tickets.md) before implementation and link the resulting tickets from the scratch record. For inline mode, track steps in the plan.
4. **Execute.** Run the engineering skill's `references/executing-plans.md` with this scratch directory. Delegate ready tasks to implementers when separate ownership or context helps. Give each implementer a bounded brief and assigned files. Use a fresh blind reviewer on each task diff and on the integrated result, following the execution skill's fallback when agents are unavailable. Apply the writing skill's `references/prose.md` to documentation or user-facing copy the feature produces.
5. **Close.** Update `status.md` with completion evidence, review findings and their disposition, and any open work. Before removing a worktree, preserve the record in an ignored scratch directory in a surviving checkout and verify the copy. Link the surviving record in the final handoff.
